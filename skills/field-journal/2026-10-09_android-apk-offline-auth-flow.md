# 2026-10-09 Android APK 离线授权链与内置载荷分析

## 场景分类

Android APK / 离线静态分析 / Kotlin 协程 / Smali 回退 / 内置原生载荷

## 可复用流程

1. 先固定原始 APK 的 SHA-256、ZIP CRC、DEX、原生库和关键 assets 清单。
2. 同时使用 JADX 与 Apktool；Java 负责高层定位，Smali 负责关键方法的事实确认。
3. 从登录布局和 Activity 找到输入入口，再沿协程类、请求构造类和响应模型恢复授权数据流。
4. 当 JADX 对关键协程方法输出 `Method not decompiled` 时，直接定位对应 Smali 方法，不根据残缺 Java 猜测。
5. 对 gzip 或其他封装的 native asset 流式解压，仅计算魔数、大小、哈希、熵和特征字符串，不执行载荷。
6. 将 Manifest、Java、Smali、脚本和载荷分别固定为 Evidence，再形成 Finding 与 callflow Path。

## 关键 Evidence 模式

- E-001：原始样本哈希、ZIP 完整性和内容清单。
- E-006：JADX 未完整还原的方法清单，为切换 Smali 提供依据。
- E-007：从 Smali 固定请求类型、证明信息、响应字段和成功结果。

## 核心 Finding

授权流程可通过“界面输入 → 协程登录方法 → 本机证明 Map → 加密传输请求 → 令牌/到期时间/并发限制 → 本地会话状态”恢复。若关键方法未反编译，Smali 可提供足够的调用链证据，但后台真实规则仍需单独授权的隔离动态分析。

## 踩坑与改进

- PowerShell 读取 Markdown 时，正则行尾需要兼容 `\r\n`；否则固定哈希可能被误报为不匹配。
- 压缩文件和解压后载荷的熵不可混用，报告中应注明测量对象。
- 未经批准不要运行内置脚本、ELF、APK 或连接其后台；静态结论应明确标记动态验证缺口。
