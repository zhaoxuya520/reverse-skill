# Agent instructions

## Scope

This repository is a client-neutral security and reverse-engineering workflow router. `RULES.md` is the behavior-chain source of truth. `skills/config/routing.json` is the routing source of truth.

## Read-only rule

Reading, summarizing, reviewing, or comparing repository files does not authorize execution. Do not run repository scripts during read-only work.

## Activation and consent

Before the first local side effect:

1. Identify the platform and task.
2. State the exact commands to run.
3. State expected file writes, downloads, network access, services, and client configuration changes.
4. Obtain explicit user approval.

Client-global rules, hooks, prompts, and MCP configuration require separate explicit approval for the selected client.

## Routing contract

For an activated task, use the platform-native route:

- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/master-route.ps1 -Hint "<task>"`
- Linux/macOS/Kali: `bash skills/scripts/master-route.sh --hint "<task>"`

Then initialize the case:

- Windows: `powershell -File skills/scripts/case-init.ps1 -Hint "<task>"`
- Linux/macOS/Kali: `bash skills/scripts/case-init.sh --hint "<task>"`

Open the returned PRIMARY skill and execute its `ACTION REQUIRED` section. Read `skills/routing.md` only when the primary route is ambiguous.

## Authorization gate

Do not act on a target until `work/<case>/scope.md` grants authorization and defines a valid network profile. An explicitly authorized local sample may use the `offline-sample` preset. `--force` and `-Force` never bypass this gate.

## Tool policy

Use paths from `skills/tool-index.md`. If the index is missing or stale, disclose and obtain approval before running the platform refresh command. Install only the tools required by the active task and only through the documented manifest.

## Evidence and output

Record conclusions as `Evidence -> Finding -> Path`. Preserve hashes and provenance. Use `skills/case-review/` before report handoff when the task produces case artifacts. Use `skills/docs-generator/` and `skills/field-journal/` only when required by the task or deliverable.

## Validation

After changes to routing or configuration, run the applicable checks:

- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/test-routing.ps1`, `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/verify-routing-coherence.ps1`, and `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/smoke.ps1`.
- Linux/macOS: `bash skills/scripts/test-routing.sh` and `bash skills/scripts/test-bootstrap-manifest.sh`.

Do not fix unrelated pre-existing issues. Preserve skills, routing behavior, scope gates, and license files. `skills/INDEX.md` is generated by `extract-summaries.ps1` from the skill files; do not hard-code client names or module counts.
